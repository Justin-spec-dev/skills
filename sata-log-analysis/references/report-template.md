# SATA 故障分析报告模板

最终报告必须使用以下结构。每个章节按内容详略自定，但章节名称和顺序保持不变。

**去重原则（重要，避免报告臃肿）**：

- 每个事实只详写一次：时间线章给"发生了什么"，关键日志解析章给"字段怎么解"，EH 章给"恢复机制如何动作"——同一段日志不要在三个章节重复解释。
- §1 是给忙人看的摘要，每条一句话，不展开证据；§10 只做证据分级（事实/判断/推测），不得复述 §1 或 §7 已给出的完整证据链。
- §5 的清单是"检查项"而非"必答问卷"：EH 行为简单时（如多次同型的 reset 即恢复），压缩为 3~5 行概括（"三次 EH 同型：hard reset 一次成功，未降速、未禁 NCQ、未离线"）加周期差异，不适用的项不写。
- §6 仅在用户提供了有效内核源码目录时保留该章节；未提供时**删除该章节**，改为在报告开头（标题下方）以一句话说明"本次分析未提供内核源码，结论基于日志与 libata 通用机制"。
